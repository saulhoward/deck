# Prototype implementation plan

Build one vertical slice at a time. Keep Pi as the only conversation/execution store; do not introduce a scheduler, replicated transcripts, or task lifecycle state machine.

The selected beep-boop lessons are **exact-object inspection, generated/validated boundary contracts and identity-preserving reconnect**; see [architecture §6, §8 and §9](architecture.md). JSON Schema will be Deck's single authored contract source, not generated output from Zig or TypeScript types. Completed items below distinguish the schema foundation and internal fresh inspection from remaining contract migration, reconciliation and public reconnect/reopen work. The [historical comparison](comparison-agent.md) predates the central-Pi decision; the architecture now links the newer pinned source review.

### Contract findings and remaining limits

`runtime/src/deck.ts` is an internal adapter, not a service entry point. Its caller must provide exclusive store ownership. Production file tools use a narrow native adapter on dedicated inherited pipes to the local Zig worker; broader environment tests still inject Pi's Node environment as a stand-in. Native bash now uses owned process groups with a dedicated cancellation channel. Remote workers are unavailable. Never run two adapters over the same store.

Pi 1.4.0 exposes `Conversation.submit(draft)` but no public `submit(tx, draft)`. The adapter first commits an immutable request capture reservation in a Pi document, then admits with the same Pi request ID. A reservation is **not** an acknowledgement. A retry repairs a crash between those commits; a committed Pi submission deduplicates a lost ACK. Metadata is also attached to the eventual input entry. This uses no internal Pi imports and no second database.

New version-3 captures explicitly label admission-time observations: model/reasoning, agent/tool cwd, extension/tool names, native-tool mode, an instruction hash and startup implementation identity. They do not snapshot instruction files or freeze a worktree. The implementation gate fingerprints actual runtime/dependency/Node/native bytes and refuses changed-code recovery while any canonical work remains; version-2/older captures keep their original weaker checks. The adapter now rejects configuration while Pi tasks/inbox remain and refuses reservation-gap repair after observed settings drift; admitted receipts and legacy capture bytes remain stable. Pi still resolves requests/phases at use time, so full per-input pinning remains a Phase 2 boundary before general public configuration. See [settings semantics](settings.md). Pending reservations are retried by the client, not independently scheduled. Task creation now uses a durable request ID and an atomic conversation/receipt commit; retries and conflicting arguments are tested across reopen.

Native FIFO and abort behavior passed: follow-ups place one at a time; steering joins at a tool boundary; abort withdraws queued input. No extra queue is needed. The supervised runtime now serves private IPC; writer-lock survival after supervisor death is tested. Foreground subagent ownership now has automated Pi/faux and crash-recovery coverage; live delegation, live ChatGPT OAuth/account eligibility, public Rex readiness/reconciliation/reopen, Tailscale, and the TUI remain unfinished/unvalidated; the API-key local workflow has user-reported manual validation. Provider/login integration now has offline fake-provider contract coverage.

## Scope discipline

# Schema-first wire contracts (initial subset)

**Implemented foundation, not complete protocol migration.** `contracts/wire.schema.json` is the single authored source for request and success/error response transport envelopes, bounded command-error records, arguments/ACKs for `admit`, `create_task`, `import_instructions`, `stop` and `rex_startup`, read-only `list_chats` arguments/items/pages, `history` arguments/page/entry/rendered-payload views, selected-chat `activity`/`progress`/`instruction_status` arguments/snapshots (including history attachments), public `rex_open`/`rex_status`/`rex_inspect` commands, the existing native Rex allocation plan/creation projection, [internal fresh inspection](rex-inspection.md) scope/query/observation/timed snapshot and [creation-receipt reconciliation](rex-reconciliation.md) lookup/evidence projection. Status/login command-specific args/results, remaining error semantics/native effects and remote workers are not yet migrated. The global `status.activity` Pi inspection is not the selected-chat activity snapshot. Those boundaries retain their existing handwritten checks. The public Rex commands now expose an explicit best-effort local workflow, without automatic effect/input replay or a readiness guarantee.

## Source and generation

The schema declares Draft 2020-12 and uses a deliberately small supported subset. `scripts/generate-contracts.mjs` produces:

- `src/generated/contracts.zig`: typed native views, structural validators over `std.json.Value` and validating typed JSON parsers;
- `runtime/src/generated/contracts.ts`: TypeScript wire types and executable type guards, with no runtime schema loading.

Do not edit generated files or duplicate these wire shapes in another language. Internal domain types may adapt them—for example, new Pi allocation intents never generate a null UUID, while legacy native records may contain null. External Rex API responses still have their own bounded validating adapter; Deck's schema does not purport to define Rex's API.

Use the pinned development shell (Node 24 and Zig 0.15.2):

```sh
nix develop -c npm run contracts:generate
nix develop -c npm run contracts:check
```

Generation formats Zig with the pinned compiler. `--check` compares both generated files without writing them. `npm run check` and the Nix build run this gate, so stale artifacts fail CI/package builds. Generation is local and deterministic; it fetches no remote schemas or tools and adds no npm dependencies. Installed runtime validation is inlined in compiled JS/native code and covered by the implementation fingerprint; neither schemas nor the generator are needed at runtime.

## Supported subset and limits

The compiler accepts local `$defs`/`$ref` without recursive references, object properties with explicit required/additional-property policy, unconstrained JSON values, strings with code-point length limits and restricted patterns, bounded safe integers, booleans/null, scalar constants, closed identifier-string enums, nullable `anyOf` pairs, bounded homogeneous arrays and bounded discriminated object `oneOf` variants. Unsupported keywords and shapes **fail generation**, rather than being ignored by one validator. Enum members are distinct ASCII identifiers beginning with a lower-case letter (`[a-z][A-Za-z0-9_]*`, including the existing `followUp` mode), generating Zig enums, TS literal unions and exact executable guards. Mixed/numeric/arbitrary-string enums fail generation. A `oneOf` requires 2–8 object branches with a common required property whose scalar constants are distinct, proving branches disjoint before generating OR guards. TS gets a union; Zig gets a tagged union with validating JSON decoding and unwrapped payload encoding (no `case0`/`case1` wire tags). Reserved Zig field names such as `error` are escaped by generation. Arrays require a supported single `items` schema and an explicit safe-integer `maxItems` from 0–4,096; optional `minItems` defaults to zero and cannot exceed that maximum. TS generates element arrays and dense-array guards; Zig generates slices and per-element guards/codecs. Tuple/prefix/contains/uniqueness constraints, unbounded arrays, nondiscriminated/general unions, formats, recursive schemas and arbitrary regexes still require a deliberate compiler extension and parity tests before use. This is not a general-purpose JSON Schema engine.

Patterns use anchored ASCII concatenations, positive character classes/ranges and bounded repetitions; variable repetition must be final. The strict end marker `$(?![\s\S])` avoids JavaScript `$` accepting a match before a trailing line terminator. Zig compiles the same restricted pattern to non-backtracking token checks. Do not replace the strict marker with `$` alone.

JSON Schema string lengths count Unicode code points, not UTF-8 bytes or UTF-16 code units. String guards additionally require well-formed Unicode; Zig's JSON parser rejects lone surrogate escapes, and TS rejects corresponding ill-formed strings. The request transport ID is now uniformly 1–200 code points, replacing Zig's byte-based and TS's UTF-16-based checks. ASCII UUID clients are unchanged. Existing path/socket/output **byte** limits remain explicit native semantic/transport checks.

Numbers are bounded within JavaScript's safe-integer range. Integral JSON numeric spellings such as `1.0`/`1e0` are accepted as integer 1; strings, fractional/out-of-range values and non-finite JS-only values are not coerced into valid integers. Opaque wire IDs remain strings. There is no canonical JSON hashing/re-encoding change.

Callers must bound encoded input before parsing: HTTP/IPC retain the 1 MiB frame/body limit, native allocation/inspection projections retain 16 KiB bounds, receipt lookup allows 128 KiB embedded request bytes/256 KiB encoded query with a 16 KiB reply, and CLI output/timeouts/capacity remain separately bounded. Schemas do not establish parser resource safety, authentication, ownership, host affinity or effect replay safety. Parsers retain their existing duplicate-member behavior; this foundation does not promise identical JSON parsing for every malformed/ambiguous input.

## Current application points

- **HTTP and private IPC:** both validate `RequestEnvelope` before dispatch. Unknown v1 envelope extensions and unknown command strings remain accepted structurally; dispatch still refuses unknown commands. `args` and `hubId` deliberately remain unconstrained at this transport layer. Command validation and hub pinning still run separately, with mismatch checked before command dispatch. Missing/non-string command fields now fail private envelope validation, matching the existing public boundary.
- **Response egress, HTTP forwarding and client ingress:** private IPC validates the actual serialized `ResponseEnvelope`, not just the in-memory TS type. Closed success/error variants require a literal boolean `ok`, version, transport ID and exactly the corresponding payload. Errors require a lower-case identifier code (1–80 code points) and a nonempty well-formed message (at most 4,096 code points); unknown well-shaped codes remain allowed. Opaque success `result` is deliberately unconstrained here, not a command-specific ACK. Serialization/shape failure yields a payload-free correlated `invalid_response`; frame overflow remains `too_large`. Dispatch may already have committed, so neither error proves no effect. Zig validates private response UTF-8/envelope and exact request-ID equality before forwarding original bytes; invalid/mis-correlated responses close that HTTP connection and stop the out-of-sync transport, without retry. The plain client independently checks the generated envelope and exact ID before exposing results/errors, then runs command-specific ACK/view checks (generated for the five mutations below). Invalid responses cannot clear input/task/import drafts; only explicit same-durable-ID retry is allowed. This is correlation, not authentication, selection-generation fencing or a complete command migration. Old fake/legacy responses without version/ID or with envelope extensions now refuse.
- **Saved mutations:** generated `AdmitArgs`/`AdmitAck`, `CreateTaskArgs`/`CreateTaskAck` and `InstructionImportArgs`/`InstructionImportAck` now guard the plain client's outgoing requests, private IPC before admission and serialized ACK egress, native HTTP ACK forwarding and client ACK consumption. `admit` and `create_task` retain their legacy extensible argument policy, but dispatch copies only declared fields—caller `origin` is ignored, never trusted. Import args remain closed, with no caller-selected file/path. All three ACKs are closed: numeric/coerced/zero/malformed IDs or extra fields refuse. Their positive decimal string IDs also require safe-integer semantic checks; import ACKs must echo the exact original chat/request identity and say `admitted:true,completion:"not_waited"`. They acknowledge admission/conversation creation, never successful inference, instruction application or external effects. Invalid post-commit ACKs become correlated `invalid_response` without redispatch; invalid private ACKs also fence native HTTP forwarding. Existing runtime UTF-16 caps (200 for durable request IDs, 200,000 for command strings) remain separate from schema code-point bounds. Nonblank content, absolute/coherent cwd, ownership, hub identity and saved worker/admission authority stay runtime checks. Prior receipt bytes, accepted hashes and local draft format are not rewritten. A legacy draft newly failing wire checks stays saved unchanged and sends nothing; this is not permission to normalize its bytes or generate another identity.
- **Stop and startup registration:** generated `StopArgs`/`StopAck` and `RexStartupArgs`/`RexStartupAck` now cover pre-send/private-dispatch validation, serialized response egress, native HTTP ACK forwarding and client consumption too. Stop retains legacy ignored argument extensions but its closed ACK is exactly `{requested:true}`—not idle, drained or rollback proof. No stop draft, durable stop receipt or automatic retry is added; an existing input draft survives stop unchanged. Startup args and ACK are closed; full UUID/block and safe Pi IDs, explicit expected envelope hub, and exact chat/allocation/block echoes are required. Its registration observation accepts only `unbound|matched` with `registered:true,historical:true,live:"not_checked"`. This is distinct from the broader internal read-only startup snapshot, whose absent/conflict diagnostics are not successful registration ACKs. Startup uses native full `REX_BLOCK`, not caller block argv; malformed output cannot unblock the client editor, admit input or create a replay draft. A saved observation may already have committed despite invalid/lost ACK. Runtime allocation/ownership/worker checks remain unchanged; correlation is not authentication or fresh health.
- **Read-only chat discovery:** generated `ListChatsArgs`, `ChatListItem`, bounded `ChatListItems` and closed `ChatListPage` cover client pre-send, private dispatch/serialized egress, native HTTP forwarding and client consumption. Limits are 1–100 scanned records (default 50); legacy request extensions are ignored/not forwarded. Required row metadata is `chatId,kind,title,machineId,cwd`; optional paired `parentChatId,ownerTaskId` links remain display hints, never ownership authority. Labels are well-formed strings of at most 200,000 code points; empty labels remain accepted, with no trimming or claim of valid/current host/cwd. Pages/items reject unknown fields. Semantic guards require positive safe string IDs, strictly ascending rows after the original cursor, count within the requested limit, paired safe links and a next cursor strictly after the request and not behind the last visible row. `next` is last **scanned**, not necessarily last displayed: empty filtered pages may advance. Whole-page validation happens before rendering/advancing; malformed/lost pages retain the prior cursor for explicit `/tasks more`, never `/retry`, draft resubmission or automatic pagination. The existing omitted/null envelope-args default is preserved; individual null command fields refuse. No discovery cache, health/lifecycle authority, new Pi task or inference is added. Oversized/malformed stored metadata can make a read fail; it is not silently clipped, repaired or skipped by validation.
- **Canonical history reads:** generated `HistoryArgs`/`HistoryPage`/`HistoryEntry` and compatible rendered-payload views now guard pre-send/private dispatch, serialized private egress, native forwarding and client consumption. Whole-page semantic guards require safe numeric v1 entry IDs (no coercion), safe string cursors, exclusive request-scoped ordering, requested limits and exact final-row `next` identity. Unlike discovery, empty history pages cannot advance. Both recent/forward polls and `/older` reject malformed rendered entries before printing anything or advancing either cursor, preserving saved drafts and existing read retry policy. Pi record extensions and unknown kinds remain opaque/unchanged, not stripped from retained history or cursor accounting. All supplied activity/progress/instruction attachments now use generated closed snapshots plus scope/UTF-16/state-result guards before the page can render or advance. Unrequested attachments refuse; requested snapshots may be omitted without clearing the display. See [history contracts and limits](history-contracts.md); this is not a full Pi/provider archive schema or another transcript store.
- **Selected-chat live views:** generated `LiveViewArgs`/`InstructionStatusArgs`, `ActivitySnapshot`, `ProgressSnapshot` and `InstructionSnapshot` (with nested enums/unions/arrays) cover pre-send/private dispatch, serialized IPC egress, native forwarding and client consumption. Activity/progress keep ignored argument extensions; instruction status remains closed. Snapshots and nested fields are closed; safe IDs, explicit chat/task echoes, existing UTF-16 budgets, progress run identity and instruction state/outcome/result consistency are semantic checks shared with Zig. Invalid reads preserve history cursors, live deduplication and existing drafts, without partial output, clearing claims or mutations. Source and historical import remain independent observations; applied provenance is not current source authority. Producer clipping now avoids splitting surrogate pairs without changing any cap or retained record. See [live-view contracts](live-view-contracts.md); no new health/lifecycle store, input or replay behavior is added.
- **Public Rex open/status/inspection:** generated closed target/open/read args, admission/reuse ACK, public binding and status snapshot plus the existing inspection snapshot cover pre-send/dispatch, serialized egress, native forwarding and client ingress. Require explicit hub pinning, safe chat/task IDs and exact ACK echoes; bound executable/socket fields and correlate status/bindings/inspection to the requested hub/chat. A read validates time/observation/exit consistency. ACKs say `bestEffort:true,completion:"not_waited"`, never readiness; malformed/lost replies do not trigger automatic retries or affect existing chat drafts. Explicit open may admit a new terminal attempt after uncertainty without replaying old accepted operations. The native plan now has an optional nonnullable full `sessionId` for new-window creation; legacy plans/receipts are not re-encoded. See [public workflow](rex-open.md).
- **Native Rex allocation input:** Zig validates/parses the generated `RexAllocationPlan`. Unknown plan fields refuse. Original worker/cwd, absolute paths, explicit socket/host/instance, executable identity, environment, timeout and cancellation checks remain semantic requirements before creation.
- **Native creation output:** Zig constructs the generated creation type and validates the serialized projection before retaining success. A malformed post-create projection remains uncertain, never a known pre-create refusal. TS validates `RexCreation` before comparing it to the saved plan and atomically applying the binding. Schema validity never substitutes for allocation/hub/chat/worker identity.
- **Fresh inspection:** generated exact scope/query and closed presence/status records validate native ingress/serialized egress and TS ingress/final timed projection. Unknown inspection fields/variants refuse, private fields are not projected, and original worker/binding/request-generation and exit-code/state consistency are separate semantic checks. Read failures become inconclusive, never missing. Inspection itself creates no read receipt or Pi task; `rex_inspect` now exposes the bounded snapshot through a validated public read command.
- **Native creation-receipt lookup:** generated query/receipt/state/hash types and validators serve a separate read-only boundary, not effect dispatch. Native checks the original operation/machine/cwd and exact byte hash; TS checks that same hash and original-plan identities before provenance apply. Missing/acceptance-only evidence cannot become allocation permission. State/creation consistency remains a semantic guard.
- **Legacy records:** absent/null allocation UUIDs remain structurally accepted. Creation-result extensions remain accepted for compatibility, but are never copied into the whitelisted public binding. Settled Pi results/retained receipts are not migrated or rewritten. New plans still bind their generated UUID semantically; startup registration remains historical, not adoption authority.

Generated Zig typed parsers are **views**, not lossless archive codecs: they can omit accepted unknown extensions and normalize absent **nullable** optional values to null when serialized. Absent **nonnullable** optional fields now have generated omission-aware object encoding, so typed argument/page views still satisfy the schema without inventing null cursors; explicitly nullable fields retain their legacy behavior. Guards enforce required/unknown-field policy at every nested object before typed decode. Typed decoding then ignores already-validated extensions so a strict parent can correctly contain an extensible legacy creation record; strict nested objects still reject unknowns. Forward the original validated HTTP bytes and preserve original retained receipts; do not round-trip them through typed views for storage/hashing/replay. Encoding a struct alone is not validation; validate serialized egress where the contract requires it.

## Validation and next boundary

`src/contracts.test.json` is the shared 315-case positive/negative corpus used by native Zig and TS tests. It covers missing/null/optional values, required/unknown fields, versions, ID formats, bounds, astral Unicode, trailing newlines, unsafe/fractional numbers, legacy projections, response discriminants/error bounds, mutation arguments/ACKs/extension policies, stop-request and historical-startup distinctions, bounded arrays/nested discovery metadata/omitted nonnullable cursors, and camel-case modes, inspection enums/scopes, explicit absent observations and bounded exit/revision fields. Zig tests also decode and re-encode typed views and require the resulting projection to remain valid. These are shape round trips, not byte/extension-preserving serialization claims.

Generator tests exercise determinism and refusal of unsupported keywords, references, patterns, numeric/array bounds, item policies, enum members and overlapping/missing-discriminator/recursive/oversized unions. A temporary schema probe executes both TS guards and native Zig codecs for array min/max, nullable elements and absent nonnullable optional arrays, without adding test-only definitions to production contracts. HTTP integration tests prove malformed envelopes are rejected without killing the writer, Unicode limits agree across both guards, and semantic argument checks remain active. Existing Pi/native Rex tests cover scope, private-field omission, retained results, stop, uncertainty and crash windows using the generated boundary.

Response tests additionally inject malformed/mis-correlated replies after a simulated committed mutation, exercise both union codecs (including nested native decoding), verify no private serialization/error diagnostics escape, and require all three draft kinds to survive invalid envelopes before explicit exact-argument retry. Native HTTP faults verify the connection/listener close without forwarding or replay. Command-specific tests additionally cover malformed/unsafe/extra-field ACKs, import scope mismatch, pre-dispatch rejection without effects, ignored legacy extensions, preserved UTF-16 caps and byte-identical legacy drafts refused before send. Administrative tests additionally refuse false/extra-field stop ACKs, wrong/malformed startup identities and live/health claims, prove stop ACKs return before held draining and preserve prior drafts, and block editor/input/draft creation on invalid startup ACKs. They require no partial invalid-page rendering, no cursor advance/automatic retry, and unchanged existing mutation drafts. Native forwarding tests cover refusal/fencing and valid sparse/terminal pages, including integral decimal/exponent limits.
